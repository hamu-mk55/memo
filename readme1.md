# 検査ナレッジ・データ活用による安定運用と工程改善：研究開発構想

作成日：2026年10月21日  
位置付け：これまでの議論を整理した研究開発計画のたたき台。個別工程での実証を通じて具体化する。外部事例・文献調査は含まない。

## 1. 目的と目指すアウトプット

検査ナレッジの構造化と検査データの蓄積を、検索・可視化にとどめず、判断、行動、効果検証、知識更新へ接続する。アウトプットは以下の2つに絞る。

| パターン | 目指す状態 | 主な利用者 | 成果指標の例 |
|---|---|---|---|
| ① 自動検査機の安定運用 | 現場作業者が状態を把握し、点検・復旧・専門家への引継ぎを実施できる | 現場作業者、保全担当者 | 停止時間、復旧時間、過検出率、問合せ件数、検査性能の維持 |
| ② 不良要因の早期分析・歩留まり改善 | 不良増加を早期に把握し、要因候補の絞り込み、検証、対策につなげられる | 生産技術、品質、工程担当者 | 発見時間、要因分析時間、不良率、歩留まり、対策効果の持続性 |

①は検査機が正しく検査できる状態の維持、②は製品不良を発生させる工程要因の低減を中心に置く。NG率の上昇が製品品質の悪化によるものか、検査機の変動によるものかを区別する技術は、両者に共通する。

## 2. 研究開発要素の全体像

情報の種類だけでなく、「その情報から何を判断し、どの行動につなげるか」で研究課題を整理する。

| 切り口 | 対象・機能 | 研究開発課題 |
|---|---|---|
| 検査ナレッジの構造化 | 不良モード、検査項目、製品規格、限度見本、閾値、判定根拠 | 用語・不良分類の統合、定性的な規格と画像特徴量の対応付け |
| 工程ナレッジの構造化 | 工程条件、設備、材料、発生機構、対策 | 発生要因・現象・対策を適用条件と確からしさ付きで表現 |
| 検査機ナレッジの構造化 | 撮像系、治具、条件、アルゴリズム | 構成と検出可能な不良・検出限界の関係の表現 |
| データ取得・標準化 | データ引き抜き、形式変換、時刻補正、共通ID | 異種装置間の意味の統一、既設機からの低負荷取得 |
| 検査の信頼性評価 | 見逃し、過検出、再現性、再判定 | 正解が不足・曖昧な条件での評価、人の判定不一致の扱い |
| 検査機の状態監視 | 輝度、ピント、位置ずれ、汚れ、スコア、処理時間 | 製品変動と撮像系劣化の識別、予兆検知 |
| データ蓄積・管理 | 画像、測定値、設定、モデル、履歴 | 判定の再現性と保存量・分析価値の両立 |
| 暗黙知・文書の知識化 | 熟練者の着眼点、調整手順、トラブル報告 | 判断理由・適用条件の抽出、矛盾・陳腐化の識別 |
| 関連付け・来歴管理 | 製品、工程、設備、画像、不良、対策 | 不完全な個体追跡、変更履歴・根拠・有効期間の管理 |
| 原因分析・工程改善 | 不良傾向、工程条件、設備履歴、対策結果 | 相関と因果の切り分け、交絡・時間差・複合要因への対応 |
| 設定・対策推奨 | 閾値、撮像条件、処理、点検・対策候補 | 見逃し・過検出・速度の両立、適用範囲と不確かさの提示 |
| 知識更新・横展開 | 新種不良、対策結果、製品変更、他ライン | 新規事象の検出、知識の有効性判断、転用条件の推定 |
| AIエージェント | 検索、照会、解析、仮説生成、報告 | 手順選択、根拠確認、判断不能時の停止・人への引継ぎ |
| 現場の意思決定・運用 | アラート、承認、役割、対応記録、教育 | 現場行動との接続、対応漏れ・過剰アラートの抑制 |

## 3. 構造化・蓄積の設計方針

### 3.1 表現する関係

| 関係 | 例 | 検討点 |
|---|---|---|
| 規格と検査 | 製品規格→不良モード→特徴量→閾値 | 規格適合を判断する根拠 |
| 不良と発生機構 | 線状キズ→原因候補→関連工程 | 同じ見え方で異なる原因の扱い |
| 不良と検出条件 | 微小凹凸→照明方向・倍率・処理条件 | 見えなかった場合と存在しなかった場合の区別 |
| 現象と対策 | 過検出増加→点検→清掃・調整→回復結果 | 対策が有効だった条件 |
| 知識と根拠 | 原因仮説→実験・報告書・発言 | 事実と経験的推測の区別 |
| 知識と適用範囲 | 推奨設定→製品・装置・材料・有効期間 | 他工程や変更後にも適用可能か |

知識は「発生状況・確認指標・対応・結果・適用条件」を一組で残す。グラフ構造化は関係を扱う手段の一つであり、実現したい検索・分析から採否を判断する。

### 3.2 蓄積する際の重要事項

- NGデータに加えて、OK画像の抽出保存や特徴量分布を検討する。
- 判定時点の撮像条件、レシピ、モデル、閾値の版を保存する。
- 検査機判定、人の再判定、精密測定、後工程での確認結果を区別する。
- 清掃、調整、保全、材料・工程条件変更と、その結果を記録する。
- 欠損、曖昧な紐付け、未確認の原因を確定情報と区別する。

## 4. パターン①：現場作業者による自動検査機の安定運用

### 4.1 出力イメージ

> 画像の明るさが基準範囲から外れ、過検出が増えています。照明窓の汚れを確認してください。清掃後は基準ワークで状態を確認し、回復しない場合は保全担当へ引き継いでください。

状態の説明、実施可能な対応、復旧確認、引継ぎ条件を一連で提示する。

### 4.2 必要技術

| 技術 | 開発内容 | 研究課題 |
|---|---|---|
| 運用知識の構造化 | 正常状態、故障モード、点検・復旧手順 | 現象・原因・対策・適用条件の表現 |
| 運転データ取得 | 画像、判定値、設定、アラーム、保全履歴 | 低負荷取得と状態再現 |
| 検査状態の監視 | 輝度、ピント、位置、スコア、時間の監視 | 品種・製品変動と装置異常の識別 |
| 原因候補の推定 | 症状と過去事例による候補の絞り込み | 類似症状の追加点検による切り分け |
| 対応支援 | 確認順序、手順、参考画像、引継ぎ先 | 作業者の権限・技能に応じた対応選択 |
| 復旧・性能確認 | 基準ワーク・画像での確認、変更記録 | 運転再開と検査性能の確認 |
| 知識更新 | 作業内容、回復結果、未解決事例の登録 | 有効な対策と偶然の回復の区別 |

### 4.3 開発ステップ

| 段階 | 実施内容 | 成果物 | 移行判断 |
|---|---|---|---|
| 1. 対象・基準の定義 | 1台・1品種群、頻発トラブル、作業範囲、正常・復旧条件を選定 | 分類、監視項目、手順、評価指標 | 正常・異常・復旧の確認方法が決まる |
| 2. 記録・可視化 | 特徴量、判定、設定変更、作業記録を時系列表示 | 監視画面、履歴データ | 過去トラブル時の変化を追跡できる |
| 3. 既知異常の検知 | ルール・統計手法で検知し、通知前に評価運転 | 検知機能、性能評価 | 正常変動を含め検知・誤警報が合意水準を満たす |
| 4. 点検・復旧支援 | 候補、確認順序、手順、復旧・引継ぎ条件を提示 | 作業者向け支援機能 | 復旧時間・対応完了率が改善し検査性能を維持 |
| 5. 展開 | 他品種・類似機へ展開、診断・対話支援を追加 | 共通知識、固有設定、展開手順 | 調整工数を抑えて効果を再現できる |

初期対象は、照明汚れ、位置ずれ、レシピ選択違いなど、原因と復旧を確認しやすいものとする。閾値自動変更に先立ち、点検・復旧支援を実証する。

## 5. パターン②：不良要因の早期分析と歩留まり改善

### 5.1 出力イメージ

> 特定不良が設備A・材料ロットBの組合せに偏っています。加工条件Cも変化しているため原因は未確定です。条件を分けた確認と該当設備の点検を推奨します。

分類、発生状況、関連工程、原因仮説、検証方法を提示する。原因確定が難しい場合も、調査対象の絞り込みを価値として評価する。

### 5.2 必要技術

| 技術 | 開発内容 | 研究課題 |
|---|---|---|
| 不良の定量化・分類 | 種類、位置、大きさ、濃淡、形状の特徴抽出 | 見え方変動への頑健性、未知・分類不能の扱い |
| 判定の信頼性確認 | 真の不良・過検出の区別、再判定との照合 | 検査機変動を品質変化と誤認しない |
| 工程との紐付け | 個体・ロットと設備、材料、条件、時刻、保全を接続 | 不完全な追跡と不確かさの扱い |
| 傾向・変化点検出 | 品種・設備・ロット別の率、特徴量、位置分布を監視 | 生産量・品種構成を考慮した早期検知 |
| 要因候補の探索 | 工程条件と不良の関係を分析 | 時間差、複合要因、交絡、相関と原因の区別 |
| 工程知識による仮説生成 | 発生機構・過去事例と分析結果の照合 | 物理・工程的妥当性の付与 |
| 検証・効果評価 | 確認・試験の提案、対策前後比較 | 他条件の影響分離、効果と持続性の評価 |
| 解析自動化 | 定型分析、根拠付き報告、結果の知識化 | エージェントの手順・結論の妥当性評価 |

### 5.3 開発ステップ

| 段階 | 実施内容 | 成果物 | 移行判断 |
|---|---|---|---|
| 1. 対象・分析単位の定義 | 重要な不良1つを選び、想定要因と必要データを整理 | 不良定義、仮説、対応表、現状指標 | 単位、不足データ、紐付け限界が明確 |
| 2. 可視化・層別 | 設備、材料、ロット、時間と紐付けて表示 | 分析データ、画面 | 現場記録と整合し、欠損・過検出の影響を説明できる |
| 3. 早期検知・要因探索 | 変化点、層別比較、特徴分析による候補提示 | 試作分析機能 | 過去・実運用で調査対象を絞れる |
| 4. 仮説検証 | 点検・測定・条件を分けた試験と効果評価 | 検証結果、対策効果、工程知識 | 介入の効果、または仮説の棄却を確認 |
| 5. 定型化・展開 | 分析自動化、エージェント、他不良・工程展開 | 支援システム、分析手順 | 分析時間短縮と改善効果を継続確認 |

初期対象は、一定の発生数があり、設備・材料等で層別でき、対策と結果確認まで可能な不良とする。

## 6. 複数工程で共通化する基盤技術

### 6.1 基本方針

全工程を同じ仕組みに合わせるのではなく、共通の枠組みに工程固有の知識・設定・モデルを組み込む。同じアルゴリズムの一律適用は前提としない。

| 基盤 | 共通化する部分 | 工程固有部分 |
|---|---|---|
| データ接続・意味の標準化 | 接続枠組み、変換、単位・時刻・欠損、取得品質確認 | 通信仕様、項目対応、周期 |
| 共通データモデル | 製品、検査、装置、設定、不良、作業、対策の構造と関係 | 規格、不良分類、固有属性 |
| トレーサビリティ・版管理 | 個体・ロット・時間の紐付け、設定・知識の来歴 | ID体系、対応関係、粒度 |
| 知識抽出・更新 | 現象・原因・確認・対策・結果の抽出と人による確認 | 用語、帳票、原因・対策内容 |
| 状態監視・変化検知 | 基準状態、分布変化、変化点、誤警報評価 | 特徴量、正常条件、品種、警報基準 |
| 診断支援 | 候補順位、追加確認選択、根拠提示 | 故障モード、点検、発生機構 |
| 要因探索・効果検証 | 層別比較、時間差分析、対策評価 | 要因候補、制約、比較条件 |
| 類似検索・転用 | 画像・数値・文章の検索、適用条件評価 | 特有の特徴、転用条件 |
| 対応・解析実行 | 手順実行、承認、引継ぎ、記録、ツール利用管理 | 手順、ツール、権限、停止条件 |
| 評価・継続改善 | 過去データ再生、検知・診断・解析評価、更新比較 | 正解、許容性能、見逃し・誤警報の重み |

### 6.2 研究所が中核技術として持つ候補

| テーマ | 共通する難しさ | 研究目標 |
|---|---|---|
| 異種情報を統合する知識表現 | 用語・分類・粒度が工程で異なる | 共通概念と固有概念を分け、対応付け・検索・分析を可能にする |
| 少量正常データによる状態監視 | 正常範囲が条件で変わり異常例が少ない | 少ないデータ・設定で正常変動と異常を識別する |
| 不完全情報からの診断・追加確認 | 観測だけでは原因が一意に決まらない | 候補を絞るための次の確認を提示する |
| 工程間の知識・モデル転用 | 類似工程でも撮像・製品特性が異なる | 転用可能性と必要な追加データ・調整を示す |
| 根拠・不確かさを扱う解析支援 | 欠損、曖昧な紐付け、相関、経験則が混在 | 事実と推測を区別し、根拠・不確かさ・検証方法を示す |

「原因を当てる」だけでなく「原因を絞るため次に何を確認するか」を決める技術を重視する。例えば安定運用では基準ワーク再撮像、工程改善では材料を揃えた設備間比較が候補となる。確認内容は個別でも、候補・根拠管理と確認の有効性評価は共有できる。

### 6.3 共通基盤の開発ステップ

| 段階 | 内容 | 検証観点 |
|---|---|---|
| 1. 2工程を選ぶ | 装置・データが異なり共通課題を持つ工程を選定 | 共通部分と固有部分の仮説 |
| 2. 最小共通構造を定義 | データ・知識・履歴と機能の入出力を定義 | 固有属性・モデルの追加可能性 |
| 3. 第1工程で実証 | 状態監視・対応支援、または要因分析を実装 | 復旧・分析時間の改善 |
| 4. 第2工程へ展開 | 接続、設定、知識、モデルを差し替え | 共通部の改修量と追加工数 |
| 5. 共通部を確定 | 繰り返す実装を抽象化し評価手順を整備 | 第3工程以降の展開容易性 |

最初の1工程で実用性を、第2工程への展開で共通性を検証する。現場効果に加え、新規工程への導入工数、必要データ量、専門家設定工数、共通部分の改修量を評価する。

## 7. 基盤整備と研究開発の切り分け

| 項目 | 主に基盤整備・システム開発 | 研究開発の焦点 |
|---|---|---|
| データ取得 | 既知仕様の取得・変換 | 不完全・異種データの意味推定、自動対応付け |
| 文書抽出 | 定型帳票からの項目抽出 | 非定型情報から原因・対策・適用条件を根拠付きで抽出 |
| 知識管理 | 定義済み情報の登録・検索 | 概念統合、矛盾検出、有効性推定 |
| 分析 | 集計、可視化、既知指標の計算 | 品質・検査機変動の分離、原因推定、効果検証 |
| エージェント | 検索・解析ツールの接続 | 状況に応じた手順選択と信頼性評価 |

既存技術の組合せでも、現場制約の下で性能を成立させることに技術的不確実性があれば、全体として研究開発課題になり得る。

## 8. 推奨する着手案と具体化事項

### 8.1 着手案

1. 第1工程で「1台の検査機の安定運用支援」と「その検査機が捉える1つの不良の要因分析」を組み合わせる。
2. 判定・設定・画像参照・作業・工程情報を結ぶ最小基盤を整える。
3. 既知トラブルの点検・復旧と、層別による要因絞り込みで現場効果を確認する。
4. 第2工程で接続・知識・設定・モデルの差替えを検証する。
5. 共通性が確認できた機能を基盤化し、診断高度化・知識転用・AIエージェントへ発展させる。

### 8.2 次に決める事項

- 実証する2工程、対象装置・品種群・不良モード。
- 現状の停止・復旧・分析時間と、期待する改善幅。
- 取得可能なデータ、ID・時刻精度、正解確認の方法。
- 現場作業者・保全・生産技術・品質の役割と対応範囲。
- 各段階の評価データ、合格基準、期間、担当。
- 共通基盤と個別開発の責任分担、導入後の更新・保守主体。

全体テーマ案は「工程固有の知識を組み込める検査運用・改善支援基盤」とし、知識表現、状態変化検知、診断・追加確認、知識転用、根拠付き解析を中核技術とする。
